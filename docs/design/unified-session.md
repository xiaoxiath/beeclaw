# 统一会话架构

本文档描述 Beeclaw 的 CLI 和飞书 Bot 统一会话管理架构。

---

## 设计理念

Beeclaw 的 CLI 和 Feishu Bot 共享统一的会话管理层，使得不同入口通道的用户获得一致的 Agent 体验：

- 相同的记忆系统
- 相同的技能访问
- 相同的对话压缩
- 相同的会话恢复

---

## 会话 ID 格式

```
{channel}-{userId}-{timestamp}
```

| 通道 | 示例 ID |
|------|---------|
| CLI | `cli-default-user-1709020800000` |
| Feishu | `feishu-ou_xxx-1709020800000` |
| API | `api-user123-1709020800000` |

## 会话持久化

会话自动持久化到 `data/memory/sessions/` 目录：

- **触发时机**：每次收到用户消息或 Agent 回复后
- **格式**：JSON 文件，按会话 ID 命名
- **并发安全**：使用文件锁（FileLock）保护写入
- **原子写入**：先写临时文件，再原子重命名

---

## 会话恢复

Beeclaw 重启后自动检测并恢复未回复的会话：

1. **启动延迟**：重启后等待 10 秒，让其他系统初始化
2. **扫描会话**：检查所有持久化的会话文件
3. **过滤条件**：
   - 最后一条消息是用户发送的（未回复）
   - 在时间窗口内（默认 24 小时）
   - 匹配当前通道（CLI 不恢复 Bot 会话，反之亦然）
4. **批量处理**：每次最多恢复 5 个会话，避免启动过载
5. **回复生成**：用原 Agent 配置重新生成回复
