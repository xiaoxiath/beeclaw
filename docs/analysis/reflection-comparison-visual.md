## 对比表格

| 维度 | Daily Reflection | Memory Compression |
|------|------------------|-------------------|
| **🎯 目的** | 改进行为和策略 | 节省存储和 token |
| **📊 处理对象** | 对话内容（语义） | 文件（磁盘） |
| **⚙️ 操作** | 分析/学习/更新 | 删除/压缩/归档 |
| **📥 输入** | 最近 50 条对话 | 7 天前的对话文件 |
| **📤 输出** | 原则更新 + 策略调整 | 摘要文件 + 归档 |
| **🧠 技术** | 模式识别 + LLM 反思 | 文件系统 + LLM 摘要 |
| **🏗️ 层次** | Application（认知层） | Infrastructure（存储层） |
| **⏰ 执行时间** | 3:00 AM | 3:30 AM (错开 30min) |
| **📊 效果** | 行为改进 +5% | 节省 85% 空间 |

## 协同工作示例

### 场景：用户多次询问股票价格

```
原始对话 (2026-03-01.md, 100KB):
User: 苹果股票现在多少钱？
Bot: 苹果股票现在是 180 美元 (错误！实际 200)
User: 你说的不对，我查了是 200
Bot: 抱歉，我应该实时查询...

...（后续多次类似错误）...

2026-03-05.md:
User: 特斯拉股票呢？
Bot: 特斯拉是 250 美元 (错误！实际 280)
User: 又错了...
```

### Memory Compression 处理：

```
1. 识别：文件已超过 7 天
2. 评分：中等重要性（包含错误但有用）
3. 操作：summarize

生成摘要 (summary-2026-03-01.md, 5KB):
2026-03-01:
- User 多次询问股票价格
- Bot 多次使用过时数据
- User 反馈错误
→ 节省 95KB 空间
```

### Daily Reflection 处理：

```
1. 分析：检测到重复失败模式
   - 3 次股票价格错误
   - 原因：未实时查询

2. 提取经验：
   "投资建议前必须核实实时价格数据"

3. 更新 SOUL.md:
   - **Verify before advising**: Financial data, prices, rates — always check current values first.

4. 归档 lessons.md:
   - 移动 "股票价格过时" 到归档
   - 已提取为原则

→ 未来行为改进：每次金融数据都会实时查询
```

## ✅ 已优化执行顺序

**当前配置**（已实现）：
```
3:00 AM  → Daily Reflection（先分析最近对话）
3:30 AM  → Memory Compression（后压缩旧文件，错开 30 分钟）
```

**优势**：
1. ✅ 避免资源竞争（CPU、内存、LLM API）
2. ✅ 避免读写冲突（Reflection 读取时 Compression 不会删除）
3. ✅ 更清晰的执行日志（分开输出）
4. ✅ 更好的错误隔离（一个失败不影响另一个）
