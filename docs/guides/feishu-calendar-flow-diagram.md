## 关键概念说明

### 1. 用户主日历 ID

```typescript
// 用户的 open_id 就是其主日历的 calendar_id
const openId = "ou_84aad35d084aa403a838cf73ee18467";
const primaryCalendarId = openId; // ✅ 正确
```

### 2. 授权 Token 类型

| Token 类型 | 用途 | 有效期 |
|-----------|------|--------|
| `tenant_access_token` | 应用访问租户数据 | 2小时 |
| `user_access_token` | **访问用户个人数据**（日历、云盘等） | 2小时 |

### 3. 权限范围

```
calendar:calendar:readonly  → 只读权限（查询日程）
calendar:calendar           → 读写权限（创建、更新、删除日程）
```

## 后续操作流程（已授权用户）

```
用户: "我明天有什么安排？"
         ↓
检查 token 缓存
         ↓
token 有效？ ──Yes──> 直接调用 API
         ↓
        No
         ↓
使用 refresh_token 刷新
         ↓
刷新成功？ ──Yes──> 保存新 token → 调用 API
         ↓
        No
         ↓
弹出授权卡片（重新授权）
```

## Token 自动刷新机制

```typescript
// 1. 从缓存获取 token
const cachedToken = getTokenFromCache(openId);

// 2. 检查是否过期
if (isTokenExpired(cachedToken)) {
  // 3. 使用 refresh_token 刷新
  const newToken = await refreshUserToken(cachedToken.refreshToken);

  // 4. 保存新 token
  saveUserToken(openId, newToken);

  return newToken.accessToken;
}

return cachedToken.accessToken;
```

## 错误处理

```
API 调用失败
    ↓
检查错误码
    ↓
99991663 (token 过期) → 清除缓存 → 重新授权
99991661 (权限不足) → 提示用户联系管理员
99991664 (日程冲突) → 返回冲突信息
其他错误 → 返回错误信息
```

## 总结

1. **首次使用**: 用户需要授权（自动弹出授权卡片）
2. **后续使用**: 自动使用缓存的 token（无感知）
3. **Token 刷新**: 自动刷新，无需手动处理
4. **日历 ID**: 用户的 `open_id` 就是其主日历的 `calendar_id`
5. **权限管理**: 创建/更新/删除需要 `calendar:calendar` 权限
6. **错误处理**: 自动处理 token 过期、权限不足等错误

整个流程对用户来说是无感知的，只需要在首次使用时点击授权，之后就可以用自然语言管理日程了！
