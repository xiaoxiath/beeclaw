## 🎨 文档设计原则

本次改造遵循以下原则：

### 1. DRY (Don't Repeat Yourself)
- README 精简，getting-started 详细
- 单一信息源，避免重复维护

### 2. 用户优先
- 从用户角度组织内容
- 场景化学习路径
- 真实案例驱动

### 3. 渐进式
- 从简单到复杂
- 每步都有检查点
- 清晰的预期成果

### 4. 可发现性
- 角色选择器
- 快速导航路径
- 交叉引用链接

### 5. 可维护性
- 文档版本管理
- 变更日志
- 明确的命名规范

## 📝 文档风格指南

虽然未创建独立的 STYLE_GUIDE.md，但已在 docs/README.md 中建立基础规范：

**命名规范**:
- ✅ 文件名：小写 + 连字符 (`memory-system.md`)
- ❌ 避免：大写、下划线 (`Memory-System.md`, `memory_system.md`)

**文档结构**:
1. 标题和简介
2. 目录（>50行文档）
3. 核心内容（结构化）
4. 示例（代码 + 配置）
5. 相关链接
